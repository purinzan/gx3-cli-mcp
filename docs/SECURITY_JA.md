# セキュリティノート

`gx3-cli-mcp` は、GX Works3 プロジェクトをローカルで読み取り解析するためのツールです。利用者が明示的に別のサービスへ送らない限り、プロジェクトデータを外部へ送信する機能はありません。

## 利用者が知るべきこと

- `.gx3` はローカルの `.gx3_cache\<sha256>\` に展開されます。
- 解析用の SQLite DB、CSV、Markdown、ZIP などがローカルに生成される場合があります。
- MCP サーバーは project-read-only の解析入口を公開します。
- MCP から合成デモ生成やプロジェクト変更系コマンドは実行できません。
- MCP が起動した解析コマンドの生成物は `GX3_MCP_OUTPUT_DIR` の中だけに制限されます。未設定時は OS の一時ディレクトリ配下の `gx3-mcp-output` を使います。
- このリリースでは MCP サーバーに license token は不要です。

## 生成される可能性があるファイル

| 種類 | 例 | 用途 |
|---|---|---|
| 展開キャッシュ | `.gx3_cache\<sha256>\` | `.gx3` 内部ファイルをローカル解析するため |
| SQLite DB | index / xref DB | デバイス検索、コメント検索、writer/reader 検索 |
| CSV / Markdown | lint, report outputs | 解析結果の確認、共有、記録 |
| ZIP | `support-bundle` | サポート用の診断情報まとめ |

通常のローカル CLI は従来どおり利用者が指定した場所へ生成できます。MCP 経由だけは、エージェントから渡された出力パスがサーバープロセスの権限で任意ファイルを上書きする confused-deputy 問題を避けるため、別のファイルシステム境界を適用します。

生成物を共有する前に、社内ルールに従って内容を確認してください。

## MCP の安全方針

- MCP は読み取り解析を中心にした allowlist です。
- GX Works3 プロジェクトを書き換える操作は MCP から公開していません。
- `gx3_run_command` は便利な escape hatch ですが、MCP-safe なコマンドだけに制限されています。
- generic tool と typed tool は同じ実行関数を通り、どちらも同じ `GX3_MCP_OUTPUT_DIR` 境界を受けます。
- `-o`、`--output`、`--out-dir`、`--db` などの名前を個別に信用して分類しません。同じ引数がサブコマンドによって入力にも出力にもなるためです。実際のファイル作成・変更時に境界を検査します。
- MCP 子プロセスは出力ディレクトリを作業ディレクトリにし、既存の相対入力は起動前に絶対パスへ直します。このため、従来の相対出力は既定で sandbox 内へ生成されます。
- Python の通常のファイル書込み、rename/delete、SQLite 作成・書込みを中央で検査します。sandbox 外の既存 SQLite は読み取り専用で開きます。
- MCP 配下から任意の外部実行ファイルを起動すると Python の書込み境界を迂回できるため、MCP sandbox 中の子プロセスは同じ Python 実行環境へ制限します。
- `live-read` は明示指定した PLC にネットワーク接続して現在値を読む CLI 専用コマンドです。MCP からは公開せず、PLC 書き込み、run/stop、download は実装しません。
- `live-read explain` と `live-read replay` は接続を開かず、採取済みのファイルだけを読みます。この2モードと `live-read modes` は MCP から利用できます（`gx3_explain_snapshot` / `gx3_replay_capture`）。
- 許可の判定はコマンド名ではなく**モード語**で行います。`live-read` は `EXTERNAL_IO_COMMANDS` に残したままで、先頭がオフラインモード語でない呼び出しは拒否されます。`live-read` を read-only コマンド一覧に入れると名前ごと許可され、ネットワークモードまで通ってしまうためです。念のため `--ip` / `--port` などネットワーク専用フラグが混ざった呼び出しも、境界の判定側で拒否します（モード側のパーサでも弾かれますが、二重に読みます）。
- 実プロジェクトを AI クライアントに扱わせる場合は、その AI クライアント側のデータ送信ポリシーも確認してください。

### この境界が保証しないこと

これは OS の権限分離やコンテナ sandbox ではありません。MCP クライアントから通常の GX3 CLI を confused deputy として使い、サーバー権限で関係ないローカルファイルを書き換える経路を狭めるためのアプリケーション層の境界です。

- パスは書込み直前に解決して sandbox 内かを確認するため、既存の symlink / junction 経由の単純な脱出は拒否します。ただし、別のローカルプロセスが検査と実際のシステムコールの間でリンクやディレクトリエントリを差し替える TOCTOU 競合まで排除するものではありません。
- `ctypes`、任意のネイティブ拡張、プロセス内へ注入されたコードなど、Python の標準ファイル API を迂回する悪意あるローカルコードを OS sandbox のように封じ込めるものではありません。
- frozen / 単一実行ファイル版で同じ起動前ガードを保証できない場合は、保護なしで実行せず fail closed します。
- `.gx3` アーカイブの通常 CLI 展開先は元ファイル横の `.gx3_cache` です。MCP sandbox 外への新規展開はこの境界により拒否されるため、MCP では既に展開済みのプロジェクトフォルダを解析対象にします。

## 運用上の注意

- このツールの出力だけで、実 PLC や生産設備への変更判断をしないでください。
- 解析結果は GX Works3 などの正式なエンジニアリング環境で確認してください。
- 安全回路、インターロック、停止条件、設備改造に関わる判断は、現場の安全確認とレビューを優先してください。
- Issue、スクリーンショット、公開資料には実プロジェクト由来の機密情報を載せないでください。
